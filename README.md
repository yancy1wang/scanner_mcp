# Scanner MCP 

## 1. 整体结构

### 
| 文件 | 作用 |
| --- | --- |
| `mcp_client.py` | 交互式客户端：LLM 工具调用循环 + 容错执行 |
| `client_defaults.py` | **新增**：纯函数容错层（端口、网段、主机、存活主机解析） |
| `local_network.py` | 执行节点宿主机网卡读取（Linux `ip -j`，优先 `enp4s0`，排除虚拟网卡） |
| `scanner_mcp_server.py` | MCP 控制面，注册工具并转发到执行面 |
| `scanner_tool_api.py` | 执行面：参数校验、网段白名单、`docker exec` 调用扫描工具 |
| `Dockerfile` / `Dockerfile.mcp` | Kali 工具容器 / MCP 服务镜像 |
---

常用命令行参数：

| 参数 | 说明 |
| --- | --- |
| `--prompt "扫描本网段"` | 单次提问后退出；省略则进入交互模式 |
| `--target 192.168.88.*` | 指定默认网段（支持通配符写法，见 2.3） |
| `--ports 22,80,8000-8100` | 指定默认端口；支持 `top` / `web` / `all` 别名 |
| `--llm deepseek` | LLM 提供方 |

启动时会打印当前生效的配置：

```
MCP 服务：http://192.168.88.233:8001/mcp｜默认端口：21,22,...｜默认网段：由 LLM 调用工具获取
```

## 2. 客户端容错机制

### 2.1 默认值优先级

```
命令行参数 --target/--ports
  > 环境变量 DEFAULT_NETWORK/DEFAULT_PORTS
    > LLM 调用 get_local_network 后确认的执行节点宿主机网段
      > 无法确定：跳过调用，提示先查询工具或补充参数
```

### 2.2 缺失/非法参数兜底表

| 缺失项 | 兜底值 | 触发场景 |
| --- | --- | --- |
| 网段 `target`（`nmap_scan`） | 配置值或 `get_local_network` 已返回的网段；没有时提示先调用查询工具 | LLM 没给或给了非法值；通配符会先解析 |
| 端口 `ports` | 常见端口 28 个：`21,22,23,25,53,80,110,111,135,139,143,443,445,993,995,1433,1521,2049,3306,3389,5432,5900,6379,8000,8080,8443,9200,27017` | 未指定、乱码、超范围、区间倒序 |
| IP/主机参数 | 已知网段内**存活主机**逐台展开（最多 32 台）；没有网段时提示先查询目标 | `ssl_check`、`ping_target`、`traceroute_target`、`whois_lookup`、`curl_headers` |
| 单主机参数收到网段 | 将网段内的可用地址逐台展开（最多 256 台） | `ssl_check`、`whois_lookup`、`ping_target`、`traceroute_target`、`nikto_scan`、`nuclei_scan`、`zap_scan`、`curl_headers`、`sqlmap_scan` |
| 域名 `domain` | 服务器地址（仅当它是域名时） | `dns_recon`、`subfinder_enum` |
| 网段过大 | 自动收窄到 `/24` | 例如 `10.0.0.0/8` → `10.0.0.0/24` |

端口别名：`common`/`default`/`默认` → 常见端口；`top`/`top100` → Top 100；
`web`/`http`；`all`/`full`/`全部` → `1-65535`。

### 2.3 通配符 / 区间写法

| 输入 | 解析结果 | 说明 |
| --- | --- | --- |
| `192.168.88.*`、`192.168.88.x` | `192.168.88.0/24` | 尾部通配符 |
| `192.168.*.*` | `192.168.0.0/16` → 收窄为 `192.168.0.0/24` | 通配符需连续到末尾 |
| `192.168.88.1-254`、`.0-255` | `192.168.88.0/24` | 末段区间 |
| `192.168.88.10-50` | `192.168.88.0/26` | 最小覆盖网段（提示可能含区间外地址） |
| `192.168.*.5`、`192.168.88.`、`192.168.88.50-10` | 不解析 | 回退默认网段并提示 |

### 2.4 存活主机发现

客户端不再使用关键词匹配判断本机意图，也不强制覆盖模型的目标参数。LLM 根据系统提示和工具描述动态调用无参数的 `get_local_ip()` / `get_local_network()`，再将返回的地址用于扫描。

两个工具读取运行 `scanner_tool_api.py` 的 Linux 宿主机，优先 `enp4s0`。如果接口不存在，只接受唯一的非虚拟网卡 IPv4；无法确认则返回错误。查询不在 Kali 扫描容器内执行。若将执行面本身部署在容器内，必须让其能访问宿主机网络命名空间，否则不能读取宿主机网卡。

成功结果示例：

```json
{"success": true, "status": "completed", "source": "scanner_tool_host", "ipv4": "192.168.88.233", "network": "192.168.88.0/24", "interface": "enp4s0"}
```

目标不明确时：
1. 若 LLM 已调用需要单主机参数的工具但漏掉 IP，客户端调用 `get_local_ip`，将返回的 `ipv4` 补入工具参数；
2. 若 LLM 没有调用工具，却对 SSL/TLS、Ping、路由追踪、HTTP 头、WHOIS 或端口扫描提出了明确执行请求，客户端同样调用 `get_local_ip` 后执行对应工具；
3. `get_local_ip` 不可用或返回失败时，调用被跳过并将错误交给 LLM；不会用 Docker 网关、traceroute 或 MCP 服务地址猜测目标；
4. 用户明确指定 IP、域名或 CIDR 时，优先使用该目标，不覆盖为本机 IP。

### 2.5 调用层容错

- **退避重试**：工具调用传输层失败最多尝试 2 次（失败后 1s 重试）。
- **健康前置检查**：发起 `nmap_scan` 前调用 `scanner_tool_health`（结果缓存 60s），后端不可达时直接跳过长扫描。
- **连接重试**：启动时连接 MCP 服务失败重试 2 次（退避 2s、4s）；已进入聊天后不再重试，避免重复执行。
- **多主机展开**：每台主机的调用单独捕获异常，单台失败不影响其余主机。
- **结果压缩**：所有工具结果先按工具类型压缩，再按多主机结果合并；总预算与显式省略标记见第 4 节。

### 2.6 覆盖范围

- 覆盖：`nmap_scan` + 只读探测类（`ssl_check`、`whois_lookup`、`ping_target`、`traceroute_target`、`curl_headers`、`dns_recon`、`subfinder_enum`）。
- `nikto_scan`、`nuclei_scan`、`sqlmap_scan`、`zap_scan` 在明确收到网段参数时会逐主机展开；缺少参数时仍把错误信息交回 LLM。
- `zeek_analyze.target` 是 PCAP 文件路径，不参与网段展开。

### 2.7 可观测性

所有兜底行为都会打印，不会静默改参数：

```
⚠️ 已将 192.168.88.* 解析为 192.168.88.0/24
⚠️ 未指定网段，使用工具确认的宿主机网段 192.168.88.0/24
⚠️ 未指定端口，使用默认端口 21,22,...
⚠️ 未指定目标 IP，使用工具确认的宿主机网段 192.168.88.0/24 内 3 台存活主机
🔎 未指定目标 IP，正在发现 192.168.88.0/24 内的存活主机...
   ↻ 调用 nmap_scan 失败（...），1s 后重试
```

## 3. 测试 Query

以下 Query 可在交互模式中逐条输入，也可以通过 `--prompt` 单次执行。请仅扫描已获得授权的目标。

### 3.1 地址查询

```text
查询本机 IP
查询本机所在网段
```

预期行为：分别调用 `get_local_ip` 和 `get_local_network`，只返回地址信息，不发起扫描。

### 3.2 Nmap 与参数容错

```text
扫描本机常见端口
扫描本网段的 22、80、443 端口
扫描 192.168.88.* 的 web 端口
扫描 192.168.88.10-50 的 top100 端口
扫描 192.168.88.0/24，不指定端口
```

预期行为：未提供目标时先查询本机 IP 或网段；通配符和区间被转换为 CIDR；端口缺失时使用默认常见端口。

### 3.3 单主机只读探测

```text
Ping 本机 4 次
检查本机的 SSL/TLS 证书
追踪到 192.168.88.1 的路由
查询 192.168.88.1 的 WHOIS 信息
获取 http://192.168.88.1 的 HTTP 响应头
```

### 3.4 端口边界与非法值

```text
调用 nmap_scan 扫描 192.168.88.1，ports 为空
调用 nmap_scan 扫描 192.168.88.1，ports 为 0
调用 nmap_scan 扫描 192.168.88.1，ports 为 65536
调用 nmap_scan 扫描 192.168.88.1，ports 为 100-10
调用 nmap_scan 扫描 192.168.88.1，ports 为 abc
调用 nmap_scan 扫描 192.168.88.1，ports 为 22,80-82,81,443
调用 nmap_scan 扫描 192.168.88.1，ports 为 1 和 65535
```

预期行为：空值、`0`、`65536`、倒序区间和非数字内容回退到默认端口；重叠端口被合并并归一化；`1` 与 `65535` 可正常使用。

### 3.5 网段边界与异常写法

```text
调用 nmap_scan 扫描 10.0.0.0/8 的 80 端口
调用 nmap_scan 扫描 192.168.*.* 的 80 端口
调用 nmap_scan 扫描 192.168.88.0/32 的 80 端口
调用 nmap_scan 扫描 192.168.*.5 的 80 端口
调用 nmap_scan 扫描 192.168.88. 的 80 端口
调用 nmap_scan 扫描 192.168.88.50-10 的 80 端口
调用 nmap_scan 扫描 999.999.999.999 的 80 端口
```

预期行为：过大的网段自动收窄到 `/24`；合法通配符转换为 CIDR；`/32` 保持为单地址网段；不连续通配符、不完整 IP、倒序范围和非法 IP 不直接传给服务端，而是回退到已配置或工具确认的默认网段。未能取得默认网段时应跳过扫描并说明原因。

### 3.6 缺失目标与工具查询失败

```text
扫描常见端口
Ping 4 次
检查 SSL/TLS 证书
获取 HTTP 响应头
执行 DNS 枚举
执行子域名枚举
```

预期行为：扫描和单主机探测先调用 `get_local_network` 或 `get_local_ip` 补全目标；DNS 和子域名枚举无法安全推断域名时应要求用户明确提供域名。若地址查询工具失败，应跳过后续调用，不得使用 Docker 网关、MCP 地址或猜测值代替。

### 3.7 单主机工具收到网段

```text
Ping 192.168.88.0/30
检查 192.168.88.0/30 的 SSL/TLS 证书
获取 192.168.88.0/30 的 HTTP 响应头
对 192.168.88.0/30 执行 WHOIS 查询
对 192.168.88.0/30 执行 Nikto 扫描
```

预期行为：先发现或展开网段内可用主机，再逐台调用对应工具；某一台失败不影响其余主机。测试时优先使用 `/30` 等小网段，避免产生大量调用。


## 4. 扫描结果压缩

客户端在把工具结果发送给 LLM 之前执行两层确定性压缩，不使用 LLM 改写原始证据：

1. `compact_tool_output()` 按工具解析单次结果，只保留状态和关键证据。
2. `compact_tool_sections()` 合并多主机结果，去重相同结果，并把连续 IP 合并为区间。

各工具保留内容：

| 工具 | 保留内容 |
| --- | --- |
| `ping_target` | UP/DOWN/ERROR、丢包率、平均延迟；多主机按状态和连续 IP 区间合并 |
| `nmap_scan` | 主机、开放端口、协议、服务和版本摘要 |
| `dns_recon` | DNS/MX/NS/TXT/DMARC 分组记录 |
| `ssl_check` | subject、issuer、有效期、协议、密码套件和证书校验结果 |
| `whois_lookup` | 域名、网段、组织、国家、注册商、日期、名称服务器和状态 |
| `nikto_scan` | 有效发现项，删除 banner、起止时间和请求统计 |
| `nuclei_scan` | 模板、严重等级、匹配目标；删除进度和加载统计 |
| `subfinder_enum` | 去重并排序后的子域名 |
| `traceroute_target` | 路由跳点，去重空行和重复行 |
| `curl_headers` | 状态行、跳转、服务端、内容类型及安全响应头 |
| `sqlmap_scan` | 可注入结论、参数、类型、payload 和后端 DBMS |
| `zeek_analyze` | 去重后的连接/数据包记录，限制记录数 |
| `zap_scan` | HTTP 状态、安全响应头和常见路径状态 |
| `get_local_ip` / `get_local_network` / `scanner_tool_health` | 紧凑 JSON，删除无关 stdout/stderr |

单次结果默认最多约 6000 字符；一次工具调用合并多个主机时，总预算为 28000 字符。预算不足时只在完整记录边界停止，并追加：

```text
[COMPRESSED_BUDGET: N complete records omitted; scan execution count remains M]
```

因此，`complete=M` 表示已经收到并处理的主机调用数；`COMPRESSED_BUDGET` 表示有完整记录未发送给 LLM。程序不再使用 `[:30000]` 从字符串中间静默截断。压缩器位于 `output_compaction.py`
